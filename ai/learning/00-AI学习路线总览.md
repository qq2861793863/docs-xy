## 各阶段学什么（一览）

### 入门（约 4~6 周）

| 模块 | 要点 |
|------|------|
| Prompt | system/user/assistant、temperature、few-shot |
| API | Node 调用、流式、会话、错误重试 |
| 结构化输出 | JSON Schema、Zod 校验 |
| RAG 入门 | embedding、chunk、向量检索 |
| 产品思维 | 可信度、重试、引用来源 |

**毕业标准**：独立做一个「上传文档 → 问答」或「业务 Chat + JSON 解析」的完整 Demo。

---

### 中级（约 2~3 个月）

| 模块 | 要点 |
|------|------|
| 进阶 RAG | Hybrid Search、Rerank、Agentic RAG、长上下文策略 |
| Agent | Tool Calling、ReAct、LangGraph 状态机 |
| MCP | Model Context Protocol、工具标准化接入 |
| 前端栈 | Vercel AI SDK 6、多步工具 UI |
| 评测 | promptfoo、LLM-as-Judge、回归测试 |
| 观测 | LangSmith / Langfuse、Trace、成本监控 |
| 安全基础 | Prompt 注入、权限边界、Key 治理 |

**毕业标准**：上线一个多用户可用的 AI 功能，有日志、有评测集、能解释「为什么这样答」。

---

### 高级（约 3~6 个月+）

| 模块 | 要点 |
|------|------|
| 微调 | SFT、LoRA、DPO、何时微调 vs Prompt |
| LLMOps | 数据飞轮、CI/CD 评测门禁、版本 lineage |
| 推理优化 | 量化、批处理、路由（小模型分流） |
| 架构决策 | RAG vs MCP vs Agent vs 长上下文 |
| 多租户 / 合规 | 审计、脱敏、内容安全、人机协同 |
| 平台化 | 统一网关、模型路由、成本配额 |

**毕业标准**：能设计团队级 AI 平台方案，并主导一次从 POC 到生产的落地。

## 如何学（通用方法）

### 1. 70% 动手 + 30% 理论

- 每学一个概念，当天写 50~100 行可运行代码
- 不要连续看三篇博客却不写项目

### 2. 一个主线项目贯穿三阶段

建议选一个你熟悉的业务场景，例如：

```
入门  →  客服 FAQ 问答（纯 RAG）
中级  →  加「查订单、创建工单」工具（Agent + MCP）
高级  →  加评测流水线 + 领域微调 + 生产监控
```

### 3. 刻意练习清单

- [ ] 同一任务用 3 种 temperature 对比输出
- [ ] 故意给错误 JSON，测校验 + 重试逻辑
- [ ] RAG 故意用差 chunk，看召回率变化
- [ ] Agent 故意给无权限工具，测安全边界
- [ ] 改 Prompt 后跑 eval，看分数是否回归

### 4. 推荐周计划（全职学习参考）

| 周次 | 入门 | 中级 | 高级 |
|------|------|------|------|
| 1~2 | Prompt + API | Hybrid RAG | 微调数据准备 |
| 3~4 | 结构化 + RAG MVP | Agent + MCP | SFT / LoRA 实验 |
| 5~6 | 产品打磨 | 评测 + 观测上线 | LLMOps + CI 门禁 |
| 7+ | — | 迭代业务功能 | 架构优化 / 合规 |

## 常见误区

| 误区 | 正确做法 |
|------|----------|
| 一上来就做 Agent | 先 RAG / 结构化输出，确认需要多步再 Agent |
| 忽视评测 | 建立 20~50 条 golden cases，改 Prompt 必跑 |
| 把所有数据都 RAG | 小数据量可直接塞进长上下文（128K+） |
| MCP 替代 RAG | MCP 拿实时数据；RAG 索引大文档库，常组合使用 |
| 微调解决一切 | 先 Prompt + RAG；微调适合固定格式 / 领域术语 |
| Key 放前端 | 永远走后端代理 + 鉴权 |
