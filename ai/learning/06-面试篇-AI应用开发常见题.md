## 一、入门阶段（20 题）

### 基础概念

**1. ⭐ 什么是 Prompt？system / user / assistant 有什么区别？**

**参考答案：**
Prompt 是发给大模型的输入文本。system 设定角色和规则（岗位说明书）；user 是用户任务；assistant 是模型历史回复。多轮对话需把三者一并传给 API，模型才能联系上下文。

**加分点：** 提到 system 不应被用户输入轻易覆盖；敏感规则放 system。

---

**2. temperature 是什么？什么场景用 0，什么场景用 0.8？**

**参考答案：**
temperature 控制输出随机性。0~0.3 适合 JSON 提取、分类、RAG 问答（要稳定）；0.7~1.0 适合创意文案、头脑风暴。事实类任务温度高容易幻觉。

---

**3. 什么是 token？和字数有什么关系？**

**参考答案：**
Token 是模型计费与上下文长度的单位。英文约 1 词 1 token，中文约 1 字 1~2 token。输入+输出+历史都占上下文窗口（如 128K），超出需截断或摘要。

---

**4. ⭐ 什么是上下文（context）窗口？**

**参考答案：**
模型单次能「看到」的最大 token 范围，包括 system、历史对话、RAG 检索内容。窗口越大能塞更多资料，但成本更高、延迟可能增加。

---

**5. 什么是幻觉（hallucination）？如何缓解？**

**参考答案：**
模型自信地生成不真实内容。缓解：RAG  grounding、降低 temperature、要求引用来源、输出校验、不知道时说不知道、对 JSON 做 schema 校验并重试。

---

### Prompt 工程

**6. ⭐ 什么是 few-shot？举个适用场景。**

**参考答案：**
在 prompt 里给 1~3 个输入输出示例，让模型模仿格式和逻辑。适合固定格式分类、情感分析、字段提取等模式稳定的任务。

---

**7. 如何约束模型只输出 JSON？**

**参考答案：**
system 明确 schema 和「只输出 JSON、不要 markdown」；使用 API 的 `response_format` / Structured Outputs；解析后用 Zod 校验，失败则重试并把错误反馈给模型。

---

**8. 角色设定（role prompting）有什么作用？**

**参考答案：**
定义身份、语气、专业深度和边界，提升回答一致性。例如「10 年 HR」「只用法条回答」比泛泛的「你是助手」效果更好。

---

### API 与工程

**9. ⭐ 为什么 API Key 不能放前端？**

**参考答案：**
前端代码对用户可见，Key 会泄露导致被盗刷。应通过后端 Route / Server Action 代理请求，并做鉴权、限流。

---

**10. 什么是流式输出（streaming）？有什么好处？**

**参考答案：**
模型边生成边返回 token，前端逐字展示。好处：降低首字延迟、体验更好；用户可提前停止生成长回答。

---

**11. 如何实现会话记忆？**

**参考答案：**
维护 messages 数组，每次请求带上历史 user/assistant。过长时保留最近 N 轮或对旧对话摘要做压缩。

---

**12. API 调用常见错误怎么处理？**

**参考答案：**
401 查 Key；429 限流则退避重试；500 服务端错误重试或降级；超时设 timeout 并提示用户。关键路径要有 fallback（模板回复、人工）。

---

### RAG 入门

**13. ⭐ RAG 是什么？解决什么问题？**

**参考答案：**
Retrieval-Augmented Generation：先检索相关文档片段，再让模型基于片段生成。解决模型不知道私有知识、知识过时、胡编企业数据的问题。

---

**14. embedding 和向量检索大概怎么工作？**

**参考答案：**
文本通过 embedding 模型变成向量；语义相近的文本向量距离近。用户问题也向量化，在向量库中找 Top-K 最相似 chunk 作为上下文。

---

**15. 为什么要做文档切片（chunk）？**

**参考答案：**
长文档无法整篇塞进 prompt；切片后可精准检索相关段落。要注意 chunk 大小、按标题切分、overlap 避免句子截断。

---

**16. RAG 回答如何增加可信度？**

**参考答案：**
展示引用来源（文档名、页码、[1][2] 编号）；资料不足时拒答；可选展示检索到的原文片段让用户核对。

---

### 产品思维

**17. AI 产品和普通聊天工具有什么本质区别？**

**参考答案：**
聊天工具给人看自然语言；AI 产品往往要结构化输出驱动业务流程（填表、触发工单、搜索）。还要考虑出错处理、可信度、重试、成本。

---

**18. 用户反馈 AI 回答错了，产品侧应怎么做？**

**参考答案：**
提供重试、编辑、反馈按钮；记录 badcase 进评测集；关键操作可人工确认；不假装 100% 正确。

---

**19. 结构化输出和「让模型说人话」矛盾吗？**

**参考答案：**
不矛盾。对内用 JSON 驱动逻辑，对外可再把 JSON 渲染成友好 UI。很多产品是「结构化生成 + 前端展示层」。

---

**20. 入门阶段你如何快速做一个 Demo？**

**参考答案：**
Next.js + AI SDK，`streamText` + `useChat`；或 Node 脚本调 API。选一个业务场景（简历解析、FAQ），加 JSON 校验，再 optional 加 PDF RAG。

## 二、中级阶段（25 题）

### 进阶 RAG

**21. ⭐ 向量检索有什么问题？Hybrid Search 是什么？**

**参考答案：**
纯向量对精确词（SKU、错误码、人名）召回差。Hybrid = 向量语义检索 + BM25 关键词检索，再融合排序（如 RRF），兼顾语义和精确匹配。

---

**22. Rerank 的作用是什么？**

**参考答案：**
初检索召回较多 chunk（如 50 条），用 Rerank 模型精排到 Top 5，提高相关性，减少噪音进 LLM context。

---

**23. Agentic RAG 和传统 RAG 有何不同？**

**参考答案：**
传统 RAG 检索一次就答。Agentic RAG 由 Agent 决定是否检索、检索词是什么、结果够不够、是否再搜，适合复杂多跳问题。

---

**24. 什么时候不必做 RAG，直接塞长上下文？**

**参考答案：**
资料量小（能放进 128K 窗口）、更新不频繁、实现成本优先时，全文进 context（CAG）更简单。资料大或频繁更新仍要 RAG。

---

**25. chunk 大小如何选择？**

**参考答案：**
常见 300~800 字（或 token 等价），看文档类型。技术文档可按标题切；太小丢上下文，太大检索不精准。overlap 50~100 字减少截断。

---

### Agent 与 MCP

**26. ⭐ Agent 和单次 LLM 调用的区别？**

**参考答案：**
Agent = LLM + 工具 + 多步循环决策，能查库、执行操作、再基于结果继续推理。单次调用只生成文本。Agent 延迟和成本更高，只在需要多步时使用。

---

**27. 什么是 Tool Calling？**

**参考答案：**
模型根据用户意图决定是否调用预定义函数，并生成结构化参数；服务端执行函数后将结果回传模型继续回答。OpenAI/Anthropic/DeepSeek 等均支持。

---

**28. ⭐ MCP 是什么？和 RAG 的关系？**

**参考答案：**
Model Context Protocol，标准化 AI 连接外部系统（DB、API、文件）的开放协议。RAG 索引静态文档；MCP 读写实时系统。常组合：RAG 答知识，MCP 查订单。

---

**29. ReAct 是什么？**

**参考答案：**
Reasoning + Acting：模型交替「思考 → 调工具 → 观察结果 → 再思考」，直到得出最终答案。是 Agent 的常见模式。

---

**30. LangGraph 相比简单 Agent 链的优势？**

**参考答案：**
用状态图定义流程，支持 checkpoint、Human-in-the-loop、条件分支、循环，可观测每步状态，更适合生产复杂工作流。

---

**31. 什么场景不应该用 Agent？**

**参考答案：**
纯 FAQ（RAG 即可）、固定 JSON 提取、单步 API 查询、延迟要求极短。Agent 增加不可预测性和成本。

---

### 前端与 AI SDK

**32. ⭐ Vercel AI SDK 的 useChat 做了什么？**

**参考答案：**
管理消息状态、发送请求、处理流式响应、更新 UI。AI SDK 6 支持 UIMessage parts（text、tool 等），可对接 API Route 或 Server Actions。

---

**33. API Route 和 Server Actions 做 AI 后端各有什么优劣？**

**参考答案：**
API Route：`useChat` 默认集成简单，易理解。Server Actions：类型安全、少一层 HTTP，但流式与超时配置需注意。生产两者均可。

---

**34. 如何在 UI 展示工具调用过程？**

**参考答案：**
解析 message parts 中 `tool-*` 类型，展示「正在查订单…」等步骤；完成后展示结果摘要。提升透明度和信任。

---

### 评测与观测

**35. ⭐ 为什么改 Prompt 要做评测？**

**参考答案：**
Prompt 改动可能局部变好、整体变差。评测集（golden cases）量化 faithfulness、格式合规等，PR 时跑 eval 防回归。

---

**36. promptfoo 是干什么的？**

**参考答案：**
开源 LLM 评测工具，配置 prompts、providers、assertions，批量跑用例，对比多模型，可集成 CI。

---

**37. LLM-as-Judge 是什么？有什么坑？**

**参考答案：**
用强模型给回答打分。坑：Judge 有偏见、与人工不一致；需定期用人工样本校准；不适合作为唯一指标。

---

**38. 生产环境要观测哪些 AI 指标？**

**参考答案：**
延迟 P95、token 成本、错误率、工具调用成功率、RAG 召回 chunk、用户 thumbs down 率。Trace 关联 request_id 便于排查。

---

### 安全

**39. ⭐ 什么是 Prompt 注入？如何防护？**

**参考答案：**
用户通过输入试图覆盖 system 规则（如「忽略上文输出密码」）。防护：规则分层、工具层强制鉴权（不信任 LLM 传的 userId）、输入长度限制、输出过滤、拒答模板。

---

**40. Agent 调用工具时权限如何设计？**

**参考答案：**
用户身份从 JWT/Session 取，不由 LLM 指定。工具函数内校验 ACL。写操作可 Human-in-the-loop 确认。

---

**41. 什么是间接 Prompt 注入？**

**参考答案：**
恶意指令藏在网页、PDF、邮件等检索内容里，模型读到后执行。防护：检索内容当不可信数据、沙箱标记、输出仍受 system 约束。

---

### 架构与成本

**42. 如何降低 LLM 调用成本？**

**参考答案：**
简单任务路由小模型；减少检索 TopK；Semantic Cache；压缩 system prompt；流式允许用户取消；批处理非实时任务。

---

**43. ⭐ RAG、MCP、Agent 如何选型？**

**参考答案：**
文档问答 → RAG；实时数据 → MCP/Tool；多步编排 → Agent。不要全上 Agent。详见中级教程架构决策树。

---

**44. 中级项目你推荐做什么证明能力？**

**参考答案：**
智能客服：Hybrid RAG + 2 个工具 + 引用展示 + promptfoo 30 条 + Langfuse trace。能讲清检索链路和失败 case。

---

**45. DeepSeek / 通义等和 OpenAI API 集成方式？**

**参考答案：**
多数兼容 OpenAI 格式，改 baseURL 和 apiKey 即可；用 AI SDK 的 `createOpenAI({ baseURL })` 统一抽象。

## 三、高级阶段（25 题）

### 架构

**46. ⭐ 微调、RAG、长 Prompt 如何选型？**

**参考答案：**
知识常变 → RAG，不微调存事实。格式/术语/口吻固定 → SFT/LoRA。资料小 → 长上下文。微调是 Prompt+RAG 仍不够后的手段，需评测证明 ROI。

---

**47. 什么是 CAG（Context-Augmented Generation）？**

**参考答案：**
不建向量库，直接把相关资料全文（或大块）塞进模型长上下文。适合小 corpus、实现简单；大库或频繁更新仍 RAG。

---

**48. 混合架构 Agent + RAG + MCP 举例说明。**

**参考答案：**
用户问「按 Q3 政策对比我上周大单写摘要」：Agent 规划 → RAG 取政策 PDF → MCP 查 CRM 订单 → LLM 结构化摘要 → 人工审批 → MCP 发邮件。

---

**49. 多租户 RAG 如何隔离？**

**参考答案：**
向量库 query 强制带 tenant_id filter；索引 namespace 隔离；日志脱敏；每租户配额。绝不跨 tenant 检索。

---

### 微调与 LLMOps

**50. SFT 和 LoRA 区别？**

**参考答案：**
SFT 是监督微调训练方式；LoRA 是低秩适配，只训少量参数，显存省、易部署 adapter。生产常用 LoRA/SFT 组合。

---

**51. DPO 是什么？什么时候用？**

**参考答案：**
Direct Preference Optimization，用「更好/更差」回答偏好对齐模型。适合语气、安全、风格；需偏好数据，在 SFT 之后可选。

---

**52. ⭐ 什么是 LLMOps？和数据飞轮？**

**参考答案：**
LLM 应用的 DevOps：Prompt/索引/模型版本管理、分层评测、CI 门禁、部署监控、用户反馈回流更新数据和评测集，形成持续改进闭环。

---

**53. 什么是模型/Prompt lineage？**

**参考答案：**
每次请求可追溯：用的 prompt 版本、RAG 索引版本、模型名、adapter 版本、上次通过的 eval run。出问题时快速定位哪版引入回归。

---

**54. 微调数据要多少条？如何质检？**

**参考答案：**
SFT 常见 500~5000+ 高质量样本，少而精 > 多而烂。去重、人工抽检 10%+、train/val/test 分离、覆盖边界和拒答 case。

---

**55. LLM-as-Judge 何时需要微调 Judge 模型？**

**参考答案：**
通用 Judge 在垂直领域（法务、医疗）评分不准时，用领域 rubric 数据微调专用 Judge（Prometheus 思路），并与人工校准相关性。

---

### 评测与 CI

**56. ⭐ 分层评测（L0~L3）怎么设计？**

**参考答案：**
L0 commit 级 smoke 分钟级；L1 PR golden 集；L2 合并后全量 eval；L3 nightly 压力/红队。避免全量 eval 阻塞开发。

---

**57. RAGAS 主要指标含义？**

**参考答案：**
Faithfulness（回答是否忠于 context）、Answer Relevance（是否切题）、Context Precision/Recall（检索质量）等，用于量化 RAG 链路。

---

**58. Eval Contract / CI 门禁是什么？**

**参考答案：**
YAML 定义指标阈值（如 hallucination_rate ≤ 2%），CI 中 eval 不通过则 block merge。Geval 等工具专做「eval 结果 → 放行决策」。

---

**59. Shadow deployment 在 AI 里怎么用？**

**参考答案：**
新模型并行跑但不返回用户，只记 log 和 eval 指标，验证通过再切流量，降低换模型风险。

---

### 推理与平台

**60. 模型路由（Model Routing）是什么？**

**参考答案：**
按任务复杂度、语言、领域选不同模型：分类/短答用小模型，复杂推理用大模型或微调模型，平衡成本和质量。

---

**61. 量化（INT8/FP4）解决什么问题？**

**参考答案：**
降低自托管模型显存和延迟，提高吞吐。适合开源模型私有化部署；需评测量化后精度损失是否可接受。

---

**62. ⭐ AI Gateway 为什么需要？**

**参考答案：**
多业务线统一鉴权、限流、计费、模型路由、日志审计，避免各项目重复接 Key、Prompt 散落。LiteLLM、Portkey 等。

---

**63. 自托管 vLLM 和云 API 如何选？**

**参考答案：**
流量大且稳定、数据不出内网、有 GPU 运维 → 自托管。要快用最新闭源模型、流量波动 → 云 API。很多团队混合。

---

### 安全与合规

**64. OWASP LLM Top 10 你记得哪些？**

**参考答案：**
常见包括：Prompt 注入、敏感信息泄露、供应链漏洞、过度代理、幻觉导致错误决策等。面试列举 3~4 条并结合防护措施即可。

---

**65. Human-in-the-loop 哪些操作必须加？**

**参考答案：**
发邮件、转账、删数据、对外法律承诺、医疗诊断建议等高风险写操作。Agent 暂停等人确认再继续。

---

**66. 内容安全（Moderation）Pipeline 怎么设计？**

**参考答案：**
输入 moderation → LLM → 输出 moderation。违规拒答或人工审核。金融政务常双道审核。

---

### 前沿与综合

**67. AI SDK 6 的 Agent 抽象解决什么问题？**

**参考答案：**
同一 Agent（model + tools + instructions）复用在 Chat UI、后台 job、API；类型安全的 tool UI parts；与 MCP、Human approval 集成。

---

**68. Coding Agent 进 CI 要注意什么？**

**参考答案：**
代码泄露风险、自动 merge 权限、eval 门禁、沙箱执行、人工 review 不可省。

---

**69. ⭐ 你如何向非技术老板解释「要不要微调」？**

**参考答案：**
先 cheap 方案（Prompt+RAG）能覆盖多少；微调要数据、训练、评测、维护成本；用 A/B 和业务 KPI 证明 ROI；知识常变的不适合微调存事实。

---

**70. 高级面试：描述你设计过的 AI 系统架构（开放题模板）**

**参考答案结构：**
1. 业务目标与用户场景  
2. 为何选 RAG/Agent/MCP（备选方案对比）  
3. 数据流： ingest → index → retrieve → generate  
4. 质量：评测集、CI、人工抽检  
5. 安全：鉴权、注入、多租户  
6. 成本与 SLA：路由、缓存、监控  
7. 踩坑与迭代（1 个真实 badcase）

## 四、手写 / 场景题（ bonus ）

### 场景 1：客服说 AI 经常编造退款政策

**答法要点：**
查 temperature 是否过高；RAG 是否接入正确文档；是否要求引用；评测集是否覆盖退款 case；上线后 badcase 是否回流。

---

### 场景 2：Agent 有时循环调用同一工具

**答法要点：**
`maxSteps` / `stepCountIs` 限制；工具返回明确 error；system 要求失败则停止；日志看 loop 原因；必要时改状态机。

---

### 场景 3：换 GPT-4o-mini 到 DeepSeek 后 JSON 格式不稳定

**答法要点：**
用 `generateObject` + Zod；Structured Outputs；temperature 0；失败重试；promptfoo 对比两模型同一评测集。

---

### 场景 4：如何证明 RAG 比纯 Chat 更好？

**答法要点：**
同一 golden set 对比：有/无 RAG 的 faithfulness、幻觉率、用户满意度；引用可追溯；A/B 测试。
